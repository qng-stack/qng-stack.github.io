第 64 章：Camera2 管线深入解析

第 64 章：Camera2 管线深入解析

相机子系统是 AOSP 中最复杂、对性能最敏感的管线之一。一次拍照可能牵涉数十个元数据键、多个输出 surface、3A（自动曝光、自动对焦、自动白平衡）收敛循环、硬件 ISP 配置与多帧降噪。所有这些工作跨越 Java 框架代码、一个原生 C++ 的 CameraService、AIDL/HIDL HAL 接口以及厂商芯片来编排。

本章追踪从面向应用的 CameraManager 一路下行经 CameraService、Camera3Device、相机 HAL，再上行经 CaptureResult 投递的完整路径。文中提到的每个类、回调和线程都标注了它在 AOSP 中的确切源文件。

64.1 Camera2 架构

64.1.1 四层栈

Camera2 子系统横跨四层：

  1. 框架 Java 层 —— android.hardware.camera2.*。应用与 CameraManager、CameraDevice、CameraCaptureSession、CaptureRequest 与 CaptureResult 打交道。

  2. 相机服务（C++） —— frameworks/av/services/camera/libcameraservice/ 中的 CameraService、CameraDeviceClient 与 Camera3Device。这个原生服务以 media.camera Binder 服务运行，管理客户端连接、强制权限并驱动 HAL。

  3. 相机 HAL —— 厂商提供的 ICameraDevice / ICameraDeviceSession 实现（AIDL 或 HIDL）。HAL 把 Camera2 的采集请求翻译成硬件 ISP 寄存器写入。

  4. 硬件 ISP / 传感器 —— 实际的图像信号处理器与传感器芯片。

64.1.7 CameraCaptureSession —— 已配置的管线

CameraCaptureSession 表示一组已配置的输出 surface。创建会话很昂贵（数百毫秒），因为相机设备必须配置内部管线并分配内存缓冲。

Source: frameworks/base/core/java/android/hardware/camera2/CameraCaptureSession.java
        frameworks/base/core/java/android/hardware/camera2/impl/CameraCaptureSessionImpl.java

会话提供两种提交采集的模式：

  1. 单次采集 —— capture(CaptureRequest, CaptureCallback, Handler) 提交一个请求，用于静态照片。

  2. 重复请求 —— setRepeatingRequest(CaptureRequest, CaptureCallback, Handler) 持续重新提交该请求，直到调用 stopRepeating() 或被新的重复请求替换，用于预览与录像。

会话还支持：

  • 连拍 —— captureBurst(List<CaptureRequest>, ...) 原子地提交多个请求。

  • 缓冲预分配 —— prepare(Surface) 预分配输出缓冲，避免首帧的分配延迟。

64.1.9 无需重新配置即可更新输出 surface（Android 17）

在 Android 17 之前，改变某条输出流写入哪个 Surface 的手段有限：finalizeOutputConfigurations() 只能一次性补上延迟 surface；updateOutputConfiguration()（单个 OutputConfiguration，API 26）只能在以 enableSurfaceSharing() 创建的输出上增删 surface。若要更换一个普通、非共享输出的 surface，就得拆掉会话再建一个新的，中间的空档会丢帧。Android 17 在 CameraCaptureSession 上新增 updateOutputConfigurations()（注意是复数），一次调用整体替换所有已配置输出的 surface：

Source: frameworks/base/core/java/android/hardware/camera2/CameraCaptureSession.java, line 1072
        frameworks/base/core/java/android/hardware/camera2/impl/CameraDeviceImpl.java, line 1289
@FlaggedApi(Flags.FLAG_SEAMLESS_TRANSITIONS)
public void updateOutputConfigurations(@NonNull List<OutputConfiguration> configurations)
        throws CameraAccessException;

列表大小必须等于会话创建时的输出数量 —— 这次调用替换 surface，不增删流。提供的每个 OutputConfiguration 按属性（尺寸、格式等）而非身份匹配回已有的流，因此新配置可以携带用 OutputConfiguration.addSurface() 加入的新 surface，也可以用 makeDeferredAndRemoveSurfaces() 重新标回延迟状态。

该方法由 FLAG_SEAMLESS_TRANSITIONS 标志门控，正是无缝使用场景切换背后的 API：应用无需重跑 createCaptureSession() 就能替换预览 surface，或补上一个延迟的采集 surface。

CameraDeviceImpl.updateOutputConfigurations() 的实现会为当前已配置的输出构建两张映射：一张以原样的配置为键，一张以其延迟形态为键；然后为每个新配置匹配一个流 ID。匹配到的流 ID 与新配置经一次 binder 调用转发：

Source: frameworks/av/camera/aidl/android/hardware/camera2/ICameraDeviceUser.aidl, line 260
void updateOutputConfigurations(in int[] streamIds, in OutputConfiguration[] configurations);

指向被替换 surface 的活动请求会被这次调用停止。当被替换的 surface 尚有在途缓冲时，框架会对旧 surface 持一个弱引用（CameraDeviceImpl 中的 mReplacedOutputs），让未完成的缓冲先排空归还，再拆掉旧的生产者连接；陈旧的条目会在下次 updateOutputConfigurations() 调用时被清理。

  2. 在部分与最终的 CaptureResult 元数据就绪时取得它们

  3. 把元数据派发给注册的 FilteredListener，再由其转发到 Java 侧

StatusTracker 监视所有流与 HAL 的就绪状态。它会合并状态更新，避免“空闲”/“活动”状态来回抖动。

64.3.7 HAL 契约

相机 HAL 必须满足严格的顺序契约：

  1. 快门通知必须按帧号顺序到达。

  2. 结果元数据必须按帧号顺序返回 —— 请求 5 的元数据必须早于请求 6 的元数据。在单个请求内部，部分结果仍可早于或晚于快门通知到达。

  3. 某条流的输出缓冲必须按 FIFO 顺序归还 —— 流 A 上请求 5 的缓冲必须在流 A 上请求 6 的缓冲之前。但不同流彼此独立，所以流 A 上请求 5 的缓冲合法地可以晚于流 B 上请求 6 的缓冲到达。

  4. 只有失败的缓冲（BufferStatus.ERROR）不受逐流严格顺序的约束

  5. REQUEST_PIPELINE_MAX_DEPTH 报告一帧从曝光到结果可用最多穿过多少级流水线。框架用它来约束自己保持的在途请求数量；管线满时 processCaptureRequest() 可能阻塞。

64.4.7 缓冲管理

相机服务里的“缓冲管理”包含两套相互独立的机制。第一套是 Camera3BufferManager，一个服务侧的图形缓冲池：它为属于同一 stream set 的输出流分配并发放 Gralloc 缓冲，也能动态释放缓冲 —— 这样做是为了让共享该集合的流不必同时都持有各自的最坏情况缓冲数量：

Source: frameworks/av/services/camera/libcameraservice/device3/Camera3BufferManager.h
        frameworks/av/services/camera/libcameraservice/device3/Camera3BufferManager.cpp

第二套独立的区分点在于：缓冲的投递由框架驱动还是由 HAL 驱动 —— 这是与 HAL 协商的 Camera3Device 模式：

框架管理的缓冲（传统方式）：

  • 相机服务取出缓冲并附加到每个请求上
  • Camera3OutputStream.getBufferLocked() 从消费者侧取出缓冲
  • 服务控制缓冲分配时机

HAL 管理的缓冲（会话 HAL 缓冲管理）：

  • HAL 通过 ICameraDeviceCallback 上的 requestStreamBuffers() 回调按需请求缓冲

  • 减少缓冲分配开销

  • 允许 HAL 跨流优化缓冲使用

64.6.8 扩展强度控制（Android 15+）

Android 15 加入扩展强度控制，让应用调节扩展效果的强度。强度是逐请求控制项 CaptureRequest.EXTENSION_STRENGTH，为 0 到 100 的单个整数：0 表示“不做后处理，返回普通帧”，100 为最大效果。只有当该键出现在扩展的 getAvailableCaptureRequestKeys() 列表中时才可用 —— 因此应用必须检查该列表，而不能假定这项控制存在：

Source: frameworks/base/core/java/android/hardware/camera2/CaptureRequest.java
  → EXTENSION_STRENGTH ("android.extension.strength")
// Check whether the chosen extension accepts a strength control
Set<CaptureRequest.Key> requestKeys =
    extChars.getAvailableCaptureRequestKeys(
        CameraExtensionCharacteristics.EXTENSION_BOKEH);

if (requestKeys.contains(CaptureRequest.EXTENSION_STRENGTH)) {
    CaptureRequest.Builder builder =
        cameraDevice.createCaptureRequest(CameraDevice.TEMPLATE_STILL_CAPTURE);
    builder.set(CaptureRequest.EXTENSION_STRENGTH, 75);  // 75% effect
}

如何解释取决于具体扩展：对 EXTENSION_BOKEH，强度控制虚化程度；对 EXTENSION_HDR 与 EXTENSION_NIGHT，它控制参与融合的帧数与结果亮度；对 EXTENSION_FACE_RETOUCH，它控制美颜平滑程度。若客户端省略该值，扩展会自选一个默认值，并在对应的采集结果中回报。

64.6.9 扩展 postview

postview 在扩展处理全分辨率输出的同时，提供一张快速的低分辨率预览图。应用检查 CameraExtensionCharacteristics.isPostviewAvailable()，从 getPostviewSupportedSizes() 中选尺寸，再经 ExtensionSessionConfiguration.setPostviewOutputConfiguration() 注册一个专用的 postview 输出 surface，快速图像随后投递到该 surface。另外，onCaptureProcessProgressed() 会上报 0 到 100 的后处理进度：

64.8 多客户端共享会话（Android 17）

在 Android 17 之前，相机是独占资源：某个相机 ID 恰好由一个客户端持有。更高优先级的客户端只能通过驱逐当前持有者来夺取它（64.2.3 节）。Android 17 增加了需主动启用的共享模式，允许多个客户端同时持有同一台相机，共同观察同一份共享流配置。这面向大屏视频会议一类场景 —— 系统的“特效”surface 与应用的 surface 想同时拿到同一传感器的帧。

64.8.1 以共享模式打开相机

共享模式是一项需主动启用的特权能力。应用先询问设备是否支持，再以共享版本的 openCamera 打开：

Source: frameworks/base/core/java/android/hardware/camera2/CameraManager.java
  → isCameraDeviceSharingSupported(String)
  → openSharedCamera(String, Executor, CameraDevice.StateCallback)
// Both APIs are @SystemApi and require SYSTEM_CAMERA + CAMERA permissions.
if (cameraManager.isCameraDeviceSharingSupported(cameraId)) {
    cameraManager.openSharedCamera(cameraId, executor, new CameraDevice.StateCallback() {
        @Override
        public void onOpenedInSharedMode(CameraDevice camera, boolean isPrimaryClient) {
            // isPrimaryClient tells this client whether it currently controls capture.
        }
        @Override
        public void onClientSharedAccessPriorityChanged(
                CameraDevice camera, boolean isPrimaryClient) {
            // Primary/secondary status can flip as higher-priority clients come and go.
        }
        @Override public void onOpened(CameraDevice camera) { /* non-shared path */ }
        @Override public void onDisconnected(CameraDevice camera) { camera.close(); }
        @Override public void onError(CameraDevice camera, int error) { camera.close(); }
    });
}

当 isCameraDeviceSharingSupported 返回 false 时，openSharedCamera 会以 UnsupportedOperationException 被拒绝；调用它还要求同时持有 android.permission.SYSTEM_CAMERA 与 android.permission.CAMERA。两个新的 StateCallback 钩子 —— onOpenedInSharedMode() 与 onClientSharedAccessPriorityChanged() —— 定义在 frameworks/base/core/java/android/hardware/camera2/CameraDevice.java。

64.8.2 主要与次要客户端

在所有以共享模式打开相机的客户端中，恰好有一个是**主要（primary）客户端，其余都是次要（secondary）**客户端。优先级来自驱逐策略所用的同样两个信号：进程状态与 OOM 分数，因此前台或系统客户端压过后台客户端。随着客户端来去，主要客户端可能变化，每个客户端都会经 onClientSharedAccessPriorityChanged() 被告知。

两种角色的能力差别很大：

能力 主要客户端 次要客户端
创建采集请求、设置任意采集参数 可以 不可以
capture / setRepeatingRequest / stopRepeating 可以 不可以
startStreaming / stopStreaming（默认参数） 可以 可以
captureBurst / setRepeatingBurst / switchToOffline / prepare 不可以（共享会话不支持） 不可以

次要客户端不能自己构造采集请求，只能通过 startStreaming(List<Surface>) 请求会话以默认参数向自己的 surface 送帧，并以 stopStreaming() 停止。

64.9.2 desktopEffects 段

desktopEffects 段暴露由相机设备自身施加的大屏视频会议特效，位于 aconfig 标志 desktop_effects 之后。其全部标签为 system 可见性，不属于公开 SDK。设备经 ANDROID_DESKTOP_EFFECTS_CAPABILITIES 公布它能施加哪些特效：

BACKGROUND_BLUR ANDROID_DESKTOP_EFFECTS_BACKGROUND_BLUR_MODE OFF、LIGHT、FULL
FACE_RETOUCH ANDROID_DESKTOP_EFFECTS_FACE_RETOUCH_MODE（+ _FACE_RETOUCH_STRENGTH） OFF、ON
PORTRAIT_RELIGHT ANDROID_DESKTOP_EFFECTS_PORTRAIT_RELIGHT_MODE OFF、ON

import android.hardware.camera2.*;
import android.media.ImageReader;
import android.view.SurfaceHolder;

public class MinimalCameraCapture {

    private CameraDevice mCamera;
    private CameraCaptureSession mSession;
    private ImageReader mImageReader;

    public void startCamera(CameraManager manager, String cameraId,
            SurfaceHolder previewHolder) throws Exception {

        // Step 1: Create ImageReader for JPEG capture
        CameraCharacteristics chars =
            manager.getCameraCharacteristics(cameraId);
        StreamConfigurationMap map = chars.get(
            CameraCharacteristics.SCALER_STREAM_CONFIGURATION_MAP);
        Size maxJpeg = map.getOutputSizes(ImageFormat.JPEG)[0];
        mImageReader = ImageReader.newInstance(
            maxJpeg.getWidth(), maxJpeg.getHeight(),
            ImageFormat.JPEG, 2);

        mImageReader.setOnImageAvailableListener(reader -> {
            Image image = reader.acquireLatestImage();
            if (image != null) {
                // Process JPEG data
                System.out.println("Got JPEG: " +
                    image.getWidth() + "x" + image.getHeight());
                image.close();
            }
        }, backgroundHandler);

        // Step 2: Open camera
        manager.openCamera(cameraId, new CameraDevice.StateCallback() {
            @Override
            public void onOpened(CameraDevice camera) {
                mCamera = camera;
                createSession(previewHolder.getSurface());
            }
            @Override
            public void onDisconnected(CameraDevice camera) {
                camera.close();
            }
            @Override
            public void onError(CameraDevice camera, int error) {
                camera.close();
            }
        }, backgroundHandler);
    }

    private void createSession(Surface previewSurface) {
        try {
            // Step 3: Create session with preview + JPEG outputs
            SessionConfiguration config = new SessionConfiguration(
                SessionConfiguration.SESSION_REGULAR,
                Arrays.asList(
                    new OutputConfiguration(previewSurface),
                    new OutputConfiguration(mImageReader.getSurface())
                ),
                executor,
                new CameraCaptureSession.StateCallback() {
                    @Override
                    public void onConfigured(CameraCaptureSession session) {
                        mSession = session;
                        startPreview(previewSurface);
                    }
                    @Override
                    public void onConfigureFailed(CameraCaptureSession session) {
                        System.err.println("Session configuration failed!");
                    }
                }
            );
            mCamera.createCaptureSession(config);
        } catch (CameraAccessException e) {
            e.printStackTrace();
        }
    }

    private void startPreview(Surface previewSurface) {
        try {
            // Step 4: Start repeating preview request
            CaptureRequest.Builder previewBuilder =
                mCamera.createCaptureRequest(CameraDevice.TEMPLATE_PREVIEW);
            previewBuilder.addTarget(previewSurface);
            mSession.setRepeatingRequest(previewBuilder.build(),
                null, backgroundHandler);
        } catch (CameraAccessException e) {
            e.printStackTrace();
        }
    }

    public void captureStillPhoto() {
        try {
            // Step 5: Submit single still capture request
            CaptureRequest.Builder captureBuilder =
                mCamera.createCaptureRequest(CameraDevice.TEMPLATE_STILL_CAPTURE);
            captureBuilder.addTarget(mImageReader.getSurface());
            captureBuilder.set(CaptureRequest.JPEG_QUALITY, (byte) 95);

            mSession.capture(captureBuilder.build(),
                new CameraCaptureSession.CaptureCallback() {
                    @Override
                    public void onCaptureCompleted(
                            CameraCaptureSession session,
                            CaptureRequest request,
                            TotalCaptureResult result) {
                        Long exposureTime = result.get(
                            CaptureResult.SENSOR_EXPOSURE_TIME);
                        Integer sensitivity = result.get(
                            CaptureResult.SENSOR_SENSITIVITY);
                        System.out.println("Captured! Exposure: " +
                            exposureTime + "ns, ISO: " + sensitivity);
                    }
                }, backgroundHandler);
        } catch (CameraAccessException e) {
            e.printStackTrace();
        }
    }
}

观察要点：

  • 每个操作本质上都是异步的
  • 预览以重复请求运行，采集是一次性请求
  • 会话必须在创建时一次性配齐所有 surface
  • JPEG 图像经 ImageReader 接收到

// Create YUV ImageReader for real-time analysis
ImageReader analysisReader = ImageReader.newInstance(
    640, 480,
    ImageFormat.YUV_420_888,
    3  // Triple-buffer
);

analysisReader.setOnImageAvailableListener(reader -> {
    Image image = reader.acquireLatestImage();
    if (image == null) return;

    // Access Y, U, V planes
    Image.Plane yPlane = image.getPlanes()[0];
    Image.Plane uPlane = image.getPlanes()[1];
    Image.Plane vPlane = image.getPlanes()[2];

    ByteBuffer yBuffer = yPlane.getBuffer();
    int yRowStride = yPlane.getRowStride();
    int yPixelStride = yPlane.getPixelStride();

    // Calculate average luminance (simple brightness meter)
    long totalLuminance = 0;
    int pixelCount = 0;
    for (int row = 0; row < image.getHeight(); row += 10) {
        for (int col = 0; col < image.getWidth(); col += 10) {
            totalLuminance += yBuffer.get(row * yRowStride + col) & 0xFF;
            pixelCount++;
        }
    }
    float avgBrightness = (float) totalLuminance / pixelCount;
    System.out.println("Average brightness: " + avgBrightness);

    image.close();  // CRITICAL: always close to return buffer
}, backgroundHandler);

观察要点：

  • YUV_420_888 保证了一种与设备无关的 YUV 格式
  • 必须尊重 PixelStride 与 RowStride（数据未必连续存放）
  • acquireLatestImage() 丢弃旧帧，避免管线回压
  • image.close() 是强制的 —— 不关闭就会泄漏缓冲

    // Create camera manager
    cameraManager = ACameraManager_create();

    // Get first camera ID
    ACameraIdList* idList = NULL;
    status = ACameraManager_getCameraIdList(cameraManager, &idList);
    if (status != ACAMERA_OK || idList->numCameras < 1) return status;

    ACaptureSessionOutput_create(window, &sessionOutput);
    ACaptureSessionOutputContainer* outputs = NULL;
    ACaptureSessionOutputContainer_create(&outputs);
    ACaptureSessionOutputContainer_add(outputs, sessionOutput);

    };

    status = ACameraCaptureSession_setRepeatingRequest(captureSession,

    ACameraManager_deleteCameraIdList(idList);

小结

Camera2 管线是 AOSP 中最精巧的子系统之一。本章的几条关键架构认识：

  1. 请求—结果模型 —— 每一帧都由应用显式请求，结果异步到达并附带逐帧的精确元数据。

  2. 三处进程边界 —— Java 框架到 cameraserver（Binder）、cameraserver 到相机 HAL（AIDL/HIDL）、HAL 到硬件。

  3. Camera3Device 是引擎 —— 它通过 RequestThread 与 StatusTracker 两个线程管理 HAL 生命周期、请求排队、结果路由与流管理；CameraDeviceClient 的 FrameProcessorBase 线程向它轮询结果元数据。

  4. 流就是 BufferQueue —— 每个输出 surface 对应一个由生产者—消费者缓冲队列支撑的 Camera3OutputStream。

  5. 元数据映射器 —— 坐标空间变换（畸变、变焦、旋转）在应用与 HAL 之间透明地施加。

  6. 扩展是在既有之上延伸，而非替换 —— 相机扩展建于 Camera2 之上，复用同一套基础设施，但加入厂商专属的多帧算法。

  7. NDK 与 Java 对等 —— NDK 相机 API 经同一个底层服务提供与 Java API 完全一致的功能。

  8. 共享模式打破单持有者规则 —— Android 17 让多个特权客户端经 openSharedCamera 同时持有同一台相机：一个主要客户端驱动采集，次要客户端针对单一设备公布的配置以默认参数送流。

  9. 元数据标签空间扩张 —— Android 17 追加 sharedSession 与 desktopEffects 两个段，后者把系统侧会议特效（背景虚化、人脸修饰、人像补光）暴露为 HAL 上报的控制项。
