附录 B：术语表

AOSP 以及本书中反复出现的关键术语、缩写与子系统名称，按字母顺序排列。

ABI（应用二进制接口，Application Binary Interface） : 编译后的代码与操作系统之间的底层接口约定。它规定了某一架构（如 arm64、x86_64、riscv64）下的调用约定、数据布局与系统调用号。

ADB（Android 调试桥，Android Debug Bridge） : 通过 USB 或 TCP 与 Android 设备通信的命令行工具与守护进程。提供 shell 访问、文件传输、应用安装与调试能力。

AIDL（Android 接口定义语言，Android Interface Definition Language） : 用于定义进程间 IPC 接口约定的接口描述语言。从 Android 12 起，现代 AIDL 在 HAL 接口上取代 HIDL，并支持 Java、C++、NDK 与 Rust 后端。

AMS（ActivityManagerService） : 负责管理应用进程、执行权限校验、并与 ATMS 协同处理 activity 生命周期的系统服务。位于 system_server 中。

ANR（应用无响应，Application Not Responding） : 应用主线程阻塞过久时触发的系统对话框。时限为：输入事件 5 秒、前台广播接收器 10 秒、后台广播接收器 60 秒。由 AMS 监控并执行 ANR 超时判定。

AOT（提前编译，Ahead-Of-Time compilation） : 在执行之前把 DEX 字节码编译为原生机器码，由 dex2oat 完成。产出存于磁盘的 OAT 文件，以缩短冷启动时间。

APEX（Android Pony EXpress） : 用于可更新系统组件（Mainline 模块）的文件格式与安装机制。APEX 是一种类 zip 的容器，内含文件系统镜像、manifest 与签名，由 apexd 管理。

ART（Android 运行时，Android Runtime） : 执行 Android 应用的托管运行时。在 Android 5.0 取代 Dalvik。它结合了 AOT 编译、JIT 编译与解释器，并配有并发垃圾回收器。

ATMS（ActivityTaskManagerService） : 管理 activity 任务栈、返回栈导航与多窗口模式的系统服务。在 Android 10 从 AMS 中拆出，以把任务管理与进程管理分离。

AVB（Android 已验证启动，Android Verified Boot） : 一种信任链机制，用密码学签名校验各启动分区的完整性。又称 vbmeta；由 bootloader 与 fs_mgr 执行。

AVF（Android 虚拟化框架，Android Virtualization Framework） : 在 Android 上启用硬件隔离虚拟机的框架。由虚拟化服务、pKVM hypervisor 与 Microdroid 客户操作系统组成。在 Android 13 引入。

Binder : Android 的主要 IPC 机制。它由内核驱动（/dev/binder）与用户空间库组合而成，在进程间提供面向对象、同步的远程过程调用，并内置引用计数与死亡通知。

Bionic : Android 自行实现的 C 库，用来取代 glibc。包含 libc、libm、libdl 以及动态链接器（linker64）。针对体积、安全（支持 MTE）与 Android 专有能力（系统属性）做了优化。

BLAST : 一个 SurfaceFlinger 内部的代号。源码中只把它展开为 “Buffer State Layer” 这条路径，并没有官方的缩写全称。它是 SurfaceFlinger 中取代旧式 BufferQueue 模型的现代缓冲提交路径，把缓冲提交与 SurfaceFlinger 事务捆绑，实现原子化、同步的更新，经由 BLASTBufferQueue 完成。

Blueprint : Soong 使用的构建描述语言。Android.bp 文件用类 JSON 的声明式语法定义模块（库、二进制、APK、APEX 包）。

BufferHub（旧式/已移除） : 曾经用于进程间零拷贝共享缓冲的系统，与旧的 VR 及低延迟显示路径相关。在现代 AOSP 中实际上已被移除：不再保留 libui 头文件，VR 支持也已消失。此处列出它，只是因为较早的资料仍会提到。

BufferQueue : 用于在进程间共享图形缓冲的生产者-消费者队列。生产者（应用）出队/入队缓冲；消费者（SurfaceFlinger）获取/释放缓冲。正被 BLASTBufferQueue 取代。

CDM（CompanionDeviceManager） : 管理 Android 设备与配套设备（手表、耳机等）之间关联关系的系统服务，提供发现、配对与权限委派。

Choreographer : Java 侧的协调器，按显示 VSYNC 信号同步调度绘制、动画与输入回调。它是 Android UI 渲染循环的心跳。

CTS（兼容性测试套件，Compatibility Test Suite） : 设备厂商必须通过才能认证 Android 兼容性的大型测试套件。测试覆盖 API 行为、权限、安全与平台特性。

Cuttlefish : Google 的可配置虚拟 Android 设备，为云端测试与开发而设计。运行在带 KVM 的 Linux 上，提供的虚拟设备比传统模拟器更接近真实硬件。

DEX（Dalvik 可执行文件，Dalvik Executable） : Android 应用的字节码格式。.dex 文件以面向内存受限设备优化的寄存器式指令集，容纳编译后的 Java/Kotlin 代码。

DisplayContent : WMS 中代表单个逻辑显示全部窗口状态的容器。持有该显示专属的窗口层级树、策略与配置。

DMA-BUF : Linux 内核框架，用于在设备与用户空间之间共享缓冲。在 Android 图形栈中被大量用于 GPU、显示、相机与视频硬件之间的零拷贝共享。

DRM/KMS（直接渲染管理器 / 内核模式设置，Direct Rendering Manager / Kernel Mode Setting） : Linux 内核的图形子系统。KMS 负责显示模式设置与翻页；DRM 管理 GPU 命令提交。HWC HAL 通常封装 DRM/KMS。

EGL : OpenGL ES 与原生窗口系统之间的接口。负责管理显示连接、渲染上下文与表面。Android 的 EGL 实现位于 libEGL.so。

Fastboot : 用于向 Android 设备刷写固件镜像的协议与工具。在操作系统启动之前的 bootloader 中运行，提供对分区的底层访问。

GKI（通用内核镜像，Generic Kernel Image） : 由 Google 维护的内核二进制，为厂商内核模块提供稳定的 ABI（KMI）。属于 Project Treble 的内核模块化工作。

Goldfish : 传统 Android 模拟器的虚拟设备平台。得名于最初基于 QEMU 的虚拟硬件。在云端测试场景正逐步被 Cuttlefish 取代。

Gralloc（图形分配器，Graphics Allocator） : 负责在设备内存中分配图形缓冲的 HAL。它拆分为 allocator（分配）与 mapper（CPU 映射）两个接口。

GTS（Google 测试套件，Google Test Suite） : 由 Google 运行的专有测试套件，用于在已认证设备上验证 GMS（Google Mobile Services）集成。与开源的 CTS 不同。

HAL（硬件抽象层，Hardware Abstraction Layer） : Android 框架与硬件相关驱动代码之间的标准化接口。HAL 把厂商实现隔离在稳定接口（AIDL 或旧式 HIDL）之后。

HIDL（HAL 接口定义语言，HAL Interface Definition Language） : Project Treble（Android 8.0）为 HAL 引入的接口定义语言。从 Android 12 起，HAL 正逐步改用 AIDL。

HWC（硬件合成器，Hardware Composer） : 驱动显示合成的 HAL。SurfaceFlinger 把图层合成委派给 HWC，由它决定使用专用硬件叠加平面，还是回退到 GPU 合成。

HWUI : Android 的硬件加速 2D 渲染库。它通过由 Skia 支撑的显示列表架构，把 Canvas 绘制命令转换为 GPU 操作。运行在专用的 RenderThread 上。

IME（输入法编辑器，Input Method Editor） : 软件键盘与文本输入框架。IME 是一种特殊服务，为文本输入提供窗口，由 InputMethodManagerService 管理。

InputFlinger : 原生输入栈（libinputflinger）。它从内核（/dev/input/）读取输入事件，处理后通过 InputDispatcher 派发到正确的窗口。与 SurfaceFlinger 不同，它不是一个独立守护进程，而由 InputManagerService 承载在 system_server 内。

Intent : Android 用于向组件请求动作的消息传递对象。Intent 可以启动 activity、service 或广播事件，由 PackageManagerService 依据已注册的 intent filter 解析。

ION : 旧式的 Android 专有内存分配器，用于在硬件组件之间共享缓冲。在现代内核中已被上游的 DMA-BUF heaps 框架取代。 JIT（即时编译，Just-In-Time compilation） : 在运行时把频繁执行的 DEX 字节码编译为原生机器码。ART 的 JIT 编译器利用剖析数据识别热点方法，在启动速度与峰值性能之间取得平衡。

JNI（Java 原生接口，Java Native Interface） : Java/Kotlin 托管代码与原生 C/C++ 代码相互调用的标准接口。ART 以快速路径优化实现 JNI，并负责托管栈与原生栈之间的切换。

Kleaf : 取代旧式 shell 脚本构建的、基于 Bazel 的内核构建系统。它提供封闭式（hermetic）构建、缓存，以及与 AOSP 构建系统更好的集成。

KMI（内核模块接口，Kernel Module Interface） : GKI 内核与厂商提供的内核模块之间的稳定 ABI。它让内核与厂商模块可以各自独立更新而不破坏兼容性。

LLNDK（LL-NDK） : 一组同时提供给平台分区与厂商分区的底层 NDK 库。包含 libc、libm、liblog、libbinder_ndk 等若干库。在各 Android 版本间保持稳定。

LMKD（低内存杀手守护进程，Low Memory Killer Daemon） : 监控内存压力（通过 PSI）并杀死后台进程以避免 OOM 的用户空间守护进程。它取代了旧式的内核内 lowmemorykiller。

Looper : Handler 与 MessageQueue 之下的原生事件循环机制。Looper 轮询文件描述符（包括 Binder）并派发消息。每个使用 Handler 的线程都有一个 Looper。

Mainline : Google 的一项计划：以 APEX 或 APK 模块的形式经由 Google Play 向核心操作系统组件交付更新，而不依赖整包 OTA。覆盖 Wi-Fi、蓝牙、媒体、DNS 等约 30 多个模块。

Microdroid : 在 pKVM 虚拟机内部使用的最小化 Android 客户操作系统。包含精简内核、init 与 payload 运行时，用于在 AVF 中运行隔离的工作负载。

MTE（内存标记扩展，Memory Tagging Extension） : ARM 的硬件特性，为内存分配附加元数据标记，以检测释放后再使用（use-after-free）与缓冲溢出类缺陷。Bionic 与内核在支持的硬件上启用了 MTE。

NDK（原生开发工具包，Native Development Kit） : 一组工具、头文件与库，让开发者可以用 C/C++ 编写 Android 应用中的部分代码。NDK 提供跨 Android 版本保证稳定的 API 表面。

NNAPI（神经网络 API，Neural Networks API） : Android 用于机器学习推理的硬件抽象 API。它通过 neuralnetworks HAL 把计算委派给加速器（GPU、DSP、NPU）。

OAT : dex2oat 产出的文件格式，内含 AOT 编译的原生机器码，以及引用 DEX 字节码的元数据（OatDexFile 头、类偏移、vmap 表）。自 Android O 起，DEX 字节码存放在配套的 VDEX 文件里而不再位于 OAT 内部。OAT 文件是一个由 ART 在运行时加载的 ELF 二进制。

OTA（空中升级，Over-The-Air update） : 以无线方式交付系统更新的机制。Android 支持 A/B（无缝）与 Virtual A/B 两种更新策略。Virtual A/B 构建在 dm-snapshot 之上。Virtual A/B 压缩（VABC）由用户空间的 snapuserd 守护进程经 dm-user 提供。

Parcel : Binder 用于跨进程边界封装数据的序列化容器。支持基本类型、IBinder 引用、文件描述符与 Parcelable 对象。

pKVM（受保护的内核虚拟机，Protected Kernel-based Virtual Machine） : 集成进 Android 内核的 hypervisor，提供硬件隔离的虚拟机。它是 AVF 的基础，在 ARM64 上运行于 EL2，以实施内存隔离。

PMS（PackageManagerService） : 负责安装、卸载与查询软件包的系统服务。它维护软件包数据库、解析 intent 并管理权限。

PSI（压力停顿信息，Pressure Stall Information） : Linux 内核机制，上报任务因等待 CPU、内存或 I/O 资源而停顿的时间占比。LMKD 依据 PSI 作出杀进程决策。

RenderEngine : SurfaceFlinger 的 GPU 合成后端。它用 Skia（GL 或 Vulkan）合成 HWC 无法以硬件处理的图层，取代了旧式基于 GLES 的 RenderEngine。

RenderThread : 每个 Android 进程中执行 GPU 绘制命令的专用线程。它把 GPU 工作与主（UI）线程解耦，使 UI 线程能在 GPU 尚未画完当前帧时就开始下一帧。

RRO（运行时资源叠加，Runtime Resource Overlay） : 一种在运行时把资源（布局、字符串、drawable）叠加到既有软件包上而不修改原始 APK 的机制。用于主题化与 OEM 定制。

SELinux（安全增强 Linux，Security-Enhanced Linux） : Android 上强制实施的强制访问控制（MAC）系统。每个进程与文件都有安全上下文；sepolicy 规则定义允许的交互。Android 以 enforcing 模式使用 SELinux。

Skia : Android 各处使用的 2D 图形库。提供 Canvas 绘制操作、文本渲染、图像解码与 PDF 生成。旧式的 Ganesh GPU 后端同时支持 OpenGL 与 Vulkan，Graphite 则是它的下一代替代品。

Soong : Android 的构建系统，处理 Android.bp 文件（Blueprint 语法）以生成 Ninja 构建规则。它在大多数模块上取代了旧式基于 Make 的构建。

SurfaceFlinger : Android 的系统合成器。从应用与系统 UI 接收缓冲，进行合成（经 HWC 和/或 GPU），并把最终帧送到显示。

SystemUI : 常驻运行的 Android 系统应用，提供状态栏、通知栏、快捷设置、锁屏、导航栏、音量对话框以及其他系统界面元素。

TEE（可信执行环境，Trusted Execution Environment） : 与主操作系统隔离的安全处理环境。Android 用 TEE（通常是 ARM TrustZone）承载 Keymaster/Keymint、Gatekeeper 与生物识别模板存储。

Tombstone : 原生进程崩溃时生成的崩溃转储文件。包含寄存器状态、回溯、内存映射及其他诊断信息。存放于 /data/tombstones/。

TradeFed（Trade Federation） : Android 的测试框架，用于运行 CTS、VTS 及其他测试套件。负责设备分配、测试执行、结果收集与报告。

Treble : Google 的 Android 架构计划（Android 8.0 起），把平台框架与厂商特有的 HAL 实现分离。通过解耦厂商分区，实现更快的系统更新。

Trusty : Google 的开源 TEE 操作系统。它运行在与 Android 并行的安全世界中，承载用于密钥管理、DRM 与安全 UI 的可信应用。

VDEX : 与 OAT 文件并存的文件格式，存放原始 DEX 字节码与校验元数据。使 ART 无需原始 APK 即可重新校验并重新优化 DEX 代码。

VDM（VirtualDeviceManager） : 创建并管理拥有独立显示、输入、传感器与音频的虚拟设备的系统服务。用于多设备体验与投屏。

VINTF（厂商接口，Vendor Interface） : 描述厂商分区与平台分区之间接口的兼容性框架。VINTF manifest 声明设备提供哪些 HAL、框架需要哪些 HAL。

VNDK（厂商 NDK，Vendor NDK） : 提供给厂商 HAL 实现使用的一组框架共享库。VNDK 快照确保厂商代码运行在已知的一套库版本之上。

VSYNC（垂直同步，Vertical Synchronization） : 显示刷新信号，用于在整个图形管线中同步渲染。Choreographer、SurfaceFlinger 与 HWC 都围绕 VSYNC 事件进行协调。

VTS（厂商测试套件，Vendor Test Suite） : 依据接口约定验证厂商 HAL 实现的测试套件。确保平台分区与厂商分区之间的 Treble 兼容性。

Vulkan : 低开销、跨平台的 3D 图形 API。Android 支持 Vulkan 作为 OpenGL ES 的替代方案，提供对 GPU 资源、命令缓冲与同步的显式控制。

WMS（WindowManagerService） : 管理窗口摆放、z 序、过渡与输入焦点的系统服务。它与 SurfaceFlinger 紧密配合，控制屏幕上可见的内容。

Zygote : 所有 Android 应用进程都从它 fork 出来的父进程。它预加载常用类与资源，使新应用进程借助写时复制（copy-on-write）的内存共享快速启动。
